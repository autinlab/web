1. Meta Quest developer setup

Get your computer and headset ready to build Unity apps for Meta Quest.

Do this once per computer and once per headset. At the end you build a test app and see it running in the headset, so you know everything works before starting real work. Plan about an hour the first time (most of it is downloads).

What you need

  • A Windows 10/11 (64-bit) PC or a Mac.
  • A Meta Quest 2, 3, 3S or Pro, and a phone with the Meta Horizon app, signed in with the account that owns the headset.
  • A data USB-C cable (some charging-only cables don't carry data; if the headset is never detected, try another cable).

Step 1 — Accounts

  1. Create a Meta developer account at developers.meta.com/horizon/sign-up and complete the account verification it asks for.
  2. Create a Unity ID at id.unity.com if you don't have one.

Step 2 — Install Unity with Android support

  1. Install Unity Hub.
  2. In Unity Hub, go to Installs → Install Editor and pick a Unity 6 version, 6000.0.66f2 or newer (the Photon VR Training sample below needs Unity 6.3).
  3. On the modules page, tick Android Build Support and, under it, OpenJDK and Android SDK & NDK Tools. All three are needed: the Quest runs Android.

Already have Unity installed without Android? In Unity Hub, click the gear next to that version → Add modules, and tick the same three.

Step 3 — Install the Meta tools

  1. Meta Quest Developer Hub (MQDH): download and install it from MQDH Getting Started, then sign in with your developer account. It shows your headset, installs apps and creates projects.
  2. Windows only — USB driver: download the Oculus ADB driver, unzip it, open the usb_driver folder, right-click android_winusb.inf and choose Install. (Not needed on Mac.)
  3. Optional, Windows only — Meta Horizon Link (the Quest Link PC app) lets you press Play in Unity and see the scene in the headset without building. Handy for quick tests, but always check with a real build too.

Step 4 — Turn on Developer Mode on the headset

  1. In the Meta Horizon app on your phone: tap the headset icon in the toolbar, tap your headset, then Headset Settings → Developer Mode, and switch it on. (It only appears once your developer account is set up — Step 1.)
  2. Restart the headset if it asks.
  3. Plug the headset into your computer with the USB-C cable and put it on.
  4. When the headset asks Allow USB debugging?, tick Always allow from this computer and choose Allow.
  5. If the prompt doesn't appear: open Quick Settings → Settings (gear) → Developer, switch on MTP Notification, then unplug and plug the cable back in.

Check: in MQDH, open Device Manager: your headset should show a green Active status. (In a terminal, adb devices should list it as device, not unauthorized.)

Step 5 — Build and run a test app

This proves that the whole chain works.

  1. In MQDH, open XR Projects → Create project. Give it a name, choose your Unity version and a folder, set XR Plugin to OpenXR and SDKs to All. The project opens in Unity. (You can also start from one of the templates in the next section.)
  2. In Unity, open Window → Meta → Tools → Project Setup Tool. In both the Android and Standalone tabs, click Fix All, then Apply All, and accept if Unity asks to change the graphics API or restart.
  3. Check Edit → Project Settings → XR Plug-in Management → OpenXR: Meta XR should be ticked, on the Android tab.
  4. Open File → Build Profiles. Under Platforms, select Meta Quest (on Unity older than 6.1: Android) and click Switch Platform (or Enable Platform). The first switch can take a while.
  5. Click Open Scene List → Add Open Scenes so your scene is included.
  6. With the headset plugged in and awake, pick it in the Run Device drop-down. (If it isn't listed, click Refresh; if still missing, go back to Step 4.)
  7. Click Build And Run and choose a folder for the .apk (for example a Builds folder next to Assets).
  8. Put on the headset: the app starts by itself when the build finishes. 🎉

To open it again later: in the headset's Library, use the filter and choose Unknown sources. You can also start, stop and uninstall it from MQDH.

When something goes wrong

What you seeWhat to do
No Developer Mode option in the Meta Horizon appThe developer account isn't finished: complete sign-up and verification (Step 1), then reopen the app.
Headset not in MQDH or Run DeviceUse a data USB-C cable, wake the headset, accept Allow USB debugging inside the headset. On Windows, install the USB driver (Step 3).
adb devices says unauthorizedPut the headset on and accept the USB debugging prompt; tick Always allow.
Build fails mentioning Android SDK, NDK or JDKThe Android modules are missing: Unity Hub → Installs → gear → Add modules → Android Build Support with OpenJDK and Android SDK & NDK Tools.
The app runs but shows a flat window, or nothing moves with your headXR isn't enabled for Android: re-run the Project Setup Tool (Fix All / Apply All) and check Meta XR under XR Plug-in Management → OpenXR, Android tab.

2. Start from a template project

In the lab we always start from a project, never from a blank folder: either the empty Meta project from MQDH → XR Projects (Step 5 above), or one of the templates below. Pick the closest one, check that it builds to the headset first (same steps as Step 5), then change it. Keep it in Git from day one.

Meta Quest (single user)

  • Empty Meta XR project: MQDH → XR Projects → Create project (OpenXR, SDKs: All). The best starting point for a new idea.
  • Meta Unity Starter Samples: small scenes for the basics (controllers, hands, passthrough, UI…).
  • All Meta Quest samples on GitHub (oculus-samples): bigger example apps, for example passthrough camera, mixed reality, multiplayer.

Multiplayer XR with Photon Fusion

Photon Fusion keeps several headsets in the same shared scene. Every Fusion project needs a free App ID from the Photon dashboard (create one for Fusion, plus one for Voice if the sample uses voice chat), pasted into the project's Photon Realtime Settings. Read each sample's page before opening it: it lists the exact Unity version and setup.

  • VR Training (the drone teaching sample): a teacher and learners go through three drone activities — naming the parts, assembling a drone, flying it. Fusion 2, Unity 6.3, with voice. Good base for teaching and lesson apps.
  • VR Shared: the simplest multiplayer VR starting point — rig, teleport and grabbing objects. Fusion 2.
  • Dragonhunters VR (Asset Store): multiplayer bow-and-arrow game with voice. Note: still on Fusion 1; use it as a reference rather than a base for new projects.
  • More: Photon's Meta Quest guide, the Photon XR samples overview, and all Photon samples.

3. Unity Claude MCP

Let Claude work inside your Unity project.

This guide connects Claude Code (the AI assistant) to the Unity Editor, so Claude can look at your scene, change objects, read the Console and run things in Unity for you. It uses a free Unity package called AI Game Developer — MCP (MCP is just the name of the "plug" between an AI and a program). No coding is needed. Plan about 15 minutes the first time.

What you need

  • Unity installed, with your project.
  • Claude Code installed and signed in (the desktop app or the terminal version).
  • An internet connection the first time (Unity downloads the package and a small helper program).

Step 1 — Add the package to your Unity project

You only do this once per project.

  1. Open your project in Unity.
  2. Open Edit → Project Settings… (on Mac, Unity → Settings… also works) and click Package Manager in the list on the left.
  3. Under Scoped Registries, click the + button and fill in exactly:
    • Name: package.openupm.com
    • URL: https://package.openupm.com
    • Scope(s): com.ivanmurzak — then click the small + under scopes and add a second line: extensions.unity
  4. Click Save (or Apply) and close the window.
  5. Open Window → Package Manager. In the top-left drop-down choose My Registries.
  6. Find AI Game Developer — MCP in the list, select it and click Install.
  7. Wait until Unity has finished (the progress bar at the bottom right disappears).

If you don't see My Registries, re-check step 3 — a typo in the URL or scope is the usual cause.

Step 2 — Open the MCP window and start it

  1. In Unity, open Window → AI Game Developer — MCP. (Shortcut: Ctrl+Alt+A on Windows, Cmd+Option+A on Mac.)
  2. The first time, the window may ask to download the server. Click Download (or Download / Retry server) and wait for it to finish.
  3. Click Connect / Start so the status turns green (connected).

Step 3 — Tell Claude Code where Unity is

The window does this for you — do not type addresses by hand.

  1. In the same MCP window, find the AI agent section.
  2. Choose Claude Code from the list.
  3. Click Configure. The status should change from Not configured to configured.

This writes a small file named .mcp.json into your project folder. It contains a local address like http://localhost:12345/... — that address is specific to your computer and project.

Step 4 — Check that it works

  1. Keep Unity open (Claude can only reach Unity while the Editor is running).
  2. Start Claude Code in your project folder (the folder that contains Assets and Packages).
    • Desktop app: open that folder as the project.
    • Terminal: cd into the folder, then type claude.
  3. If Claude asks whether to trust/enable the MCP server ai-game-developer, say yes.
  4. Type /mcp and press Enter. You should see ai-game-developer marked as connected.
  5. Try a first request, for example: "List the objects in the open Unity scene."

Everyday use

  • Open Unity first, then Claude Code.
  • If you restart Unity, the connection usually comes back by itself. If Claude says it can't reach Unity, open Window → AI Game Developer — MCP and click Connect again, then type /mcp in Claude Code and reconnect.
  • Claude will ask before doing things; read what it proposes before saying yes, especially for changes to scenes and prefabs. Keep your project in version control (Git) or make a backup copy, so any change can be undone.

When something goes wrong

What you seeWhat to do
/mcp shows ai-game-developer — failed, or "connection refused"Unity is closed, or the MCP window isn't connected. Open Unity, open the MCP window, click Connect, then reconnect in Claude Code with /mcp.
It worked yesterday, not todayThe address may have changed. In the MCP window, choose Claude Code again and click Configure, then restart Claude Code.
The package isn't in the Package ManagerRe-check the scoped registry (Step 1, point 3): URL https://package.openupm.com, scopes com.ivanmurzak and extensions.unity.
The server won't startIn Unity: Tools → AI Game Developer → Server → Download Binaries, then Connect again. Tools → AI Game Developer → Server → Open Logs shows what went wrong — send that to whoever helps you.
Everything is confusedTools → AI Game Developer → Reset Config, then redo Steps 2 and 3.
Two Unity projects open at the same timeEach project gets its own address. Run Claude Code in the folder of the project you want, and make sure that project's MCP window is connected.

Good to know

  • Everything runs on your own computer: the address is localhost, which means "this machine".
  • The .mcp.json file is per computer. If you share the project with others, each person runs Step 3 on their own machine.
  • Package home page and help: github.com/IvanMurzak/Unity-MCP (the window also has Help / Talk and YouTube Tutorial buttons).

4. Blender Claude MCP

Let Claude build and edit scenes in Blender.

This guide connects Claude Code to Blender with the free MCP for Blender add-on, so Claude can inspect your scene, create and change objects and materials, take viewport screenshots and run Blender Python for you. Plan about 10 minutes the first time.

What you need

  • Blender 3.0 or newer.
  • Claude Code installed and signed in.
  • An internet connection the first time.

Step 1 — Run the installer

One command installs uv (the small tool that runs the server) if you don't have it, adds Blender to Claude Code, and installs and enables the Blender add-on. It keeps your existing settings and saves a .bak copy of any file it changes.

Windows (PowerShell):

powershell -ExecutionPolicy ByPass -c "irm https://www.mcp-for-blender.com/install.ps1 | iex"

Mac / Linux (Terminal):

curl -LsSf https://www.mcp-for-blender.com/install.sh | sh

When it lists the AI apps it found, pick Claude Code. Already have uv? Run uvx mcp-for-blender setup instead.

Step 2 — Restart and connect

  1. Fully quit Claude Code and start it again.
  2. Open Blender. The add-on starts its server when Blender opens.
  3. To check: in the 3D viewport press N, open the MCP for Blender tab, and click Start MCP Server if it isn't running.
  4. In Claude Code, type /mcp: blender should be connected. Try "Describe the objects in my Blender scene."

If the installer doesn't work: manual setup

  1. Install uv with its official installer (not pip install uv): 
    powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
    On Mac: brew install uv. Other options: docs.astral.sh/uv.
  2. Add the server to Claude Code: 
    claude mcp add blender uvx mcp-for-blender
    On Windows, if Claude Code can't start uvx, use instead: 
    claude mcp add blender -- cmd /c uvx mcp-for-blender
  3. Install the add-on: uvx mcp-for-blender install-addon, then in Blender go to Edit → Preferences → Add-ons and enable Interface: MCP for Blender.
  4. Continue with Step 2 above.

Everyday use

  • Open Blender first, then Claude Code.
  • Save your .blend file before asking for big changes. Claude can run any Python code inside Blender.
  • Ask in small steps ("add a sphere above the cube", then "make it metallic") rather than one huge request.
  • Connect only one AI app to Blender at a time (for example Claude Code or Claude Desktop, not both).

When something goes wrong

What you seeWhat to do
/mcp shows blender failed, or Claude can't reach BlenderMake sure Blender is open and the server is running (N → MCP for Blender → Start MCP Server). Don't run the uvx command yourself in a terminal. The first request sometimes fails; try again.
spawn uvx ENOENTClaude can't find uvx. On Windows use the cmd /c form from the manual setup, or point to the full path shown by where uvx.
TimeoutsBreak the request into smaller steps.
Blender freezes while downloading a Poly Haven assetDownloads block Blender until they finish; ask for 1k or 2k textures instead of larger ones.
Still stuckQuit and restart both Claude Code and Blender.

Good to know

  • Blender and the server talk over localhost (port 9876), on your own computer.
  • Older setups that use uvx blender-mcp keep working; the package was renamed mcp-for-blender.
  • Telemetry: by default the add-on sends only minimal anonymous usage data (tool names, success, timing); your prompts, code and screenshots are sent only if you opt in under Edit → Preferences → Add-ons → MCP for Blender. To turn it off completely, add the server with claude mcp add blender -e DISABLE_TELEMETRY=true -- uvx mcp-for-blender (run claude mcp remove blender first if it's already there).
  • Project home page and full docs: github.com/ahujasid/mcp-for-blender.
